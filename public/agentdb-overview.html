Cache Snowflake data in ThoughtSpot

Agent DB lets customers cache the model data they query live from Snowflake into the ThoughtSpot data store — cutting live query cost and speeding up loads. This page explains what we're building, the workflow, and exactly what's in scope for the MVP.

How it works

Queries are served from the cache instead of hitting Snowflake live. Anything outside the cached window still routes live.

Two ways to cache a model

Chosen with the Cache scope control in caching settings.

Full Model simplest
Cache every table, all history. One decision.
  • All tables cached
  • All history (no time limit)
  • Only editable setting: refresh frequency
Custom cost control
Per-table time windows for large models.
  • Every table defaults to All history
  • Switch a table to a window: last 1 / 3 / 6 / 13 months
  • Windowed table needs a reference date column
  • Older rows fall back to live Snowflake

Scope for the MVP

In scope

  • Full-model caching (one click + refresh frequency)
  • Custom per-table time windows (1 / 3 / 6 / 13 months) + reference column
  • Schedule: frequency, time, exclude weekends, timezone
  • Operate: refresh, purge, disable, edit
  • Data store capacity view (bought / used / available)
  • Run history + per-table run breakdown
  • Cached indicator on the model list

Not in scope (yet)

  • Selecting a subset of tables to cache
  • Per-table refresh frequency
  • Row-level filters on what gets cached
  • Column-level selection (open question)
