The person, and the two seconds

Arjun is an Editor at Acme Retail. Five pipelines load into AgentDB overnight. He opens the console at nine with one question: did it all land? Then he looks for a table, checks it is fresh, and maybe runs a query. Once a quarter he adds a key or a person. In his first week he did the heavy lifting: tables, keys, loads, ThoughtSpot.

So the landing page has two seconds to answer his question, and the rest of the page is for finding things. Today it spends its loudest type on inventory. Storage 394 GB at 32px. Tables 10 at 32px. The one number he came for, 1 failed, is a 12px footnote under Loads, and it is the only word on the page that should be red.

Five moves follow, heaviest first. Each keeps the 14 and 15 Oct rulings. Each is a surgical change to one or two files.

1

Signal before inventory

One status line replaces the four tiles. A dot, a sentence, a link into the failed load. The figures move to the right, at text size, where the eye goes second. Your 15 Oct ruling holds: the metrics stay on top, above the browser. They just stop shouting.

TouchesDataPage only. StatTile leaves the Data page; the same strip serves Queries in move 3.

2

The product's canvas

White page, grey sidebar. That is the sidebar you showed me, and in the product the page beside it is white. Tonight both are the same grey, separated by a hairline, and every section floats in its own white card. Cards on grey is the dashboard idiom, VeloDB's. The product's idiom is sections on white, separated by whitespace and the Table's own header band.

The browser keeps its border, because a tree and a pane need an edge between them. Everything else loses the card: the tiles (gone in move 1), the panels on Queries, API keys and Connect. Tables sit straight on the page. The mockups above and below are all drawn this way.

Touchesthe shell background, Panel and StatTile in the pages that use them. No new components.

3

Queries: status before type

The two jobs on this page are "find the one that failed" and "stop the one that is running away". Both are status. So status becomes the second column, right after time, and the status filter becomes a row of chips with counts, so the failed ones are one click away and the count is visible before the click. Type becomes a segmented control, four options. Tables and users stay dropdowns; those lists are long.

The "All queries" heading goes: it repeats the page title. The four tiles become the strip from move 1, with Failed in red.

TouchesActivityPage. SegmentedControl and Chip are Radiant components already in the library.

4

SQL: the editor is the page

This is the only way to create anything, and the critical first-week job. Tonight it is a ten-row text area in the middle of a grey page with a small Run button. The editor should own the height: editor on top, results below, the split sized so both are always on screen. Run is the one primary button on the page, with the shortcut on it. The database selector sits where the eye starts, top left of the editor. Nothing else is added: no starter statements, as ruled.

TouchesSqlPage layout and the editor's height rule. SplitPane is in the library if you want the divider draggable; a fixed 55/45 split is enough for the prototype.

5

Connect: the thing to paste comes first

Nobody reads this page. They copy from it and leave. Tonight the thing they came for, the connection string, is the last line under a sentence, two pickers and four facts. Put it first, big, with one Copy. The four facts go into a two-column grid under it, each with its own copy, for the tools that want fields instead of a string. The two pickers stay above, they are the only inputs. The list of tools becomes a footnote. The tabs stay, as ruled.

TouchesConnectPage only. Apps, Agents and Load data get the same shape: the paste-able thing first, its inputs above, its facts below.

Smaller, in the same pass

ChangeWhy, from his seat
One relative time format for Last updated and Last used everywhere: 4 min ago · 3 h ago · Yesterday, 09:14 · 2 Sep.Tonight a column mixes "4 min ago", "Today, 02:04" and "Yesterday, 09:14". He has to do arithmetic to compare rows.
Database page columns: Name · Kind · Last updated · Rows · Size.Freshness is the daily check; size is the monthly one. Put the daily one beside the name.
One primary button per page, top right: Run, Create API key, Add person, Create service account. Data, Queries and Connect have none.Tells him what the page is for before he reads it.
Drop headings that repeat the page title: "All queries", "Keys", "Connect a tool".Each costs a line and says nothing he does not know.
API keys: the sentence "To load data with a key, see Connect" becomes a tertiary link in the header row.A sentence under a title reads as a warning. A link reads as a door.
Empty workspace: the status line reads "No loads yet" with the grey dot, and the figures read 0 GB, 1 database, 0 queries.The same strip, honest about day one, instead of four empty cards.

What I would not touch

  • The sidebar. Set today. The light AppSidebar, text only, the person at the foot.
  • The tree. Kind icons on objects earn their place: a view and a table need telling apart at a glance.
  • The tables, dialogs and confirmations. Radiant's, and right.
  • Sign in. One card, three steps, nothing to add.
  • The gear. Prototype chrome, bottom right, out of the way.

If you say go

  1. The canvas: white page, Panel and StatTile retired from the pages. One shell change, then each page loses its cards.
  2. Data: the status line and figures. Last updated beside the name. One time format.
  3. Queries: status second column, chips with counts, segmented type, the strip.
  4. SQL: the split, Run as the primary with the shortcut.
  5. Connect: the string first, facts in a grid.

Each step is tsc and build clean before the next. You look between steps, or at the end. Say which numbers, or all, or none.

Honest limits. I drew these from the code, not from the screen; I have not seen tonight's build render. The proportions are close, the exact pixel rhythm is not. Every sentence in the mockups is placeholder copy.
