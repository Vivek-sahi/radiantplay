Demo 1 · The console about 3 minutes · Acme Retail six weeks in

Gear button, bottom right: Workspace › Filled workspace, and under Demo make sure Live is unticked. Nothing in this demo touches the state file the second demo uses.
1

Data Browser

The one list of everything: twelve objects across two databases, tables, a view, a materialised view. Pick acme_retail in the database filter. Open orders.

On the table: Columns, Sample data, History. History shows last night's loads: the one at 02:00 that timed out with nothing written, and the retry at 02:04 that landed 412 million rows. Point at Load instructions ↗, you will come back to it.

What is in the database, and what happened to it, from the database's own records.

2

SQL Browser

The workbench. Paste, then Cmd+Enter:

SELECT region, SUM(amount) AS revenue
FROM acme_retail.orders
WHERE order_date >= '2026-10-01'
GROUP BY region
ORDER BY revenue DESC;

Then create a table. Paste in a new tab, Cmd+Enter. The result says the table exists and links to Load instructions.

CREATE TABLE acme_retail.returns (
  return_id BIGINT,
  order_id BIGINT,
  returned_at DATETIME,
  amount DECIMAL(12,2),
  reason VARCHAR(64)
)
UNIQUE KEY(return_id)
DISTRIBUTED BY HASH(return_id) BUCKETS AUTO;

One editor for everything: reads, and the only way tables are created. No forms.

Glance: Data now lists returns, 0 rows, waiting for its first load.

3

Queries Browser

One log of everything the database ran: reads, writes, loads, under the account that sent them. Set Status to Failed: the orders load that timed out, the tickets load that hit a bad value, a query from support-copilot refused for lack of permission, one from churn-analyst refused at the rate limit.

Click the tickets load: the exact row and value. Click the churn-analyst one: refused at ten queries a second. Set Status back to all and find the In progress query: that is where Cancel lives.

Evidence, in the database's words. This is what an agent reads too.

4

Connect Browser

Ingestion: pick the key shopify-sync, tick orders and returns, open the SeaTunnel tab. The job's sink block, filled in: address, key, database, tables. Open "Values for tools set up through a form" for the field-by-field version.

Consumption: the connection string any MySQL-speaking tool uses. ThoughtSpot is one BI tool in the list, alphabetically.

Agents: the MCP address and the config to paste into Claude Code or Cursor.

Nobody reads this page. They copy from it and leave. That config is where the second story starts.

5

API keys and Members Browser

API keys: every tool's identity, with what it may do: Query, or Query and load. Rotate and revoke in the row menu. Members: people and their roles.

Who may do what. The same keys are what an agent gets.

Demo 2 · Claude Code about 9 minutes · a new account, operated from the terminal

Reset first. In the terminal:
agentdb reset

Then open the console with Live on. It lands on Data, empty:

http://localhost:5190/playground/AgentDBMVP?live=1

Start Claude fresh in the demo folder:

cd ~/agentdb-demo && claude
1

Take a key to your agent Browser

API keys › Create API key. Name claude-code, access Query and load. Create. Copy the secret while the dialog is open; it is shown once.

The last thing you do in the UI is take a key to the agent.

2

Connect Terminal

Connect to AgentDB with this key: PASTE_THE_SECRET_HERE. Tell me what is in it.

Glance: API keys, claude-code, last used just now.

3

Create the tables Terminal

Create tables in acme_retail for Shopify orders, customers and refunds. The columns are in shopify-schema.sql.

Glance: Data lists orders, customers, refunds, 0 rows, waiting for first load. The schema file stands in for the DDL exported from the shop's Postgres.

4

Point the ETL tool at them, run the first load Terminal

Set up our SeaTunnel job to load orders, customers and refunds from the shop's Postgres into those tables, and run it. Tell me when the data has landed.

Glance: Queries shows three loads under shopify-sync, refunds Failed with the row error. Data shows rows on orders and customers. Optional: Connect › Ingestion, key shopify-sync, three tables, SeaTunnel tab: the same block Claude fetched.

Claude created the pipeline's identity, fetched the recipe, wrote the job, ran it, and read the evidence.

4b

Fix it where the fault is Terminal optional

Do that.

Glance: refunds now has rows; a second load, Completed. If Claude already fixed it on its own, skip this.

5

Look at what landed Terminal

Show me how many orders landed and the five latest ones.

Glance: Queries, the two SELECTs under claude-code with data read.

5b

Model it Terminal optional, for a data-engineer audience

Create orders_daily in acme_retail: revenue by day and region from orders, kept up to date.

Glance: Data lists orders_daily as a materialised view, refresh after each load.

6

An agent workload arrives Terminal

Say: "Meanwhile, the analytics team's agent runs its churn task." Then type this line in the Claude session. The ! runs it as a shell command.

! agentdb demo churn-task

Glance: Queries fills with forty rows under churn-analyst, two Failed. Set User to churn-analyst.

7

What failed, and why Terminal

What failed in the last hour, and why?

Claude lists the refunds load (fixed), a query refused because churn-analyst may not read refunds, and one refused at the rate limit, and asks what to do.

Give it refunds. Keep the limit.

Glance: Queries, Status Failed, click the refused refunds query and the failed load: the words Claude reasoned from. API keys: churn-analyst reads refunds.

8

Who uses what, and a check that keeps watching Terminal

Which tables were queried this week, by whom, and which were not? Then set up a weekly check that posts unused tables to #data-eng.

Glance: nothing new in the console. Claude shows the usage table, the script in checks/, and the cron line.

9

Close Browser

Queries. Set User to claude-code, then shopify-sync, then churn-analyst.

If something goes wrong

What you seeWhat to do
Claude says "Unknown or revoked key"The key did not reach the state file: Live was off when you created it. Tick Live in the gear menu, create another key with a new name, use that secret.
Claude asks for the Postgres host or passwordSay: "Use the known source in your notes."
Claude fixes the refunds load without askingFine. Skip 4b.
Claude tries to do something by hand instead of with the commandSay: "Use the agentdb command."
The browser stops following the terminalThe state server is down. In any terminal: agentdb serve. Reload the browser.
You want to start overagentdb reset, reload the browser, /clear in Claude or start it again.
You want to see the state without the browseragentdb status, agentdb tables, agentdb queries
