The claim the demo makes

A data engineer opens AgentDB once, takes a key to their coding agent, and never has to come back for the work: connecting the pipeline, modelling, finding out what failed and why, seeing who uses what. When they do come back, it is to look at evidence, not to click through screens.

Proves

  • Set up in under two minutes
  • Build and load from Claude Code
  • Tables created first, the ETL tool pointed at them, load evidence read from one place
  • Agent workloads show up as tasks with cost and failures
  • Engineers extend it with their own checks

Does not prove

  • Faster or cheaper than anyone. That is a benchmark, not a demo
  • That the console is unnecessary. It shows a lifecycle that does not need it

How it runs on your Mac

No copy of the prototype. The prototype stays where it is and gains one switch, Live, in its gear menu. Three parts work together:

  1. A state file. One JSON file holding what the console shows: databases, tables, loads, queries, keys. In Live mode the console re-reads it every second, so whatever changes the file changes the browser.
  2. An agentdb command. A small program that reads the state file, does what it was told, writes the file back and prints a result. For SQL it reuses the engine already inside the prototype.
  3. A demo folder with a note for Claude. ~/agentdb-demo/ holds the command, a CLAUDE.md that says "AgentDB is operated with the agentdb command, here are its subcommands", and the prompts file. You start Claude Code inside this folder. It cannot see the prototype's code, so it cannot edit it. All it can do is run the command.

What is on screen

One browser window and one terminal window, side by side. That is all the audience sees.

Browser · left, about 60%
The AgentDB console in Live mode. You click here only in the first beat and glance at it at the evidence moments.
Terminal · right, about 40%

$ claude
> Connect to AgentDB with this key …

You type the prompts here. Claude runs agentdb commands. The browser reacts.

Two processes run hidden: the prototype's dev server (npx vite --port 5190) and the state server (agentdb serve). You start both before recording and hide them. Nobody types there and no Claude session runs in the background. There is exactly one Claude Code session, the one you are typing into on screen. The console runs as v6 with Live on: localhost:5190/playground/AgentDBMVP?live=1.

Where the MCP version goes

Not in today's build. Later, the same program is served as MCP tools instead of a command. Beat 1 then ends with claude mcp add and a "Claude Code connected" indicator in the console, and the terminal shows agentdb · run_sql tool calls instead of Bash lines. Every other beat is identical. It becomes necessary when the audience is customers or the exec team and the MCP connection is part of the claim.

The commands

Everything Claude can run. The note in the demo folder lists exactly these, with one line each, so Claude never guesses.

agentdb demo churn-taskWrites the forty churn queries under one task id, two failingTask summary
The rule. The console and Claude are two clients of the same capabilities. If the console can do it, the command can. If the command did it, the console shows it under the agent's name. What stays in the console is policy, not capability: account birth, a secret shown once, other people's sign-in and approvals, plan and security settings.
Destructive statements. agentdb sql refuses DROP and TRUNCATE unless --confirm is passed, and the note tells Claude to ask you first. Not in the story, but it is there if someone asks "what stops it dropping a table".

What is real, what is a stand-in

Real

  • Claude Code, live, reasoning over real command output
  • The console, the v5 prototype
  • The DDL and SELECTs, run by the prototype's SQL engine
  • The evidence texts, in the shape Doris produces them

Stand-in

  • The database itself is a state file, not Doris
  • seatunnel-demo is not SeaTunnel. It reads the real job file and fakes the loads
  • The churn agent is a script, not another model
  • The command replaces the MCP connection the product will ship

If anyone asks, say so. The claim is about the workflow and the evidence, and both are shown honestly.
