How Git works

Your work lives on its own branch

The main Radiant Play repo is always safe. You branch off, build your prototype, then merge back when it's ready — or just keep it on your branch forever.

main branch
The live Radiant Play repo on Galaxy. Always stable. Only changes after a reviewed Pull Request is merged in.
your branch
Your personal workspace. Invisible to everyone until you open a PR. Build, break, experiment — main is never affected.

Before you start

Two things to set up

One-time setup. Takes about 5 minutes total.

1

Galaxy account

Your ThoughtSpot login works here. Sign in and confirm you can see the Radiant Play repo. Can't access it? Message your team lead on Slack.

galaxy.corp.thoughtspot.com
2

Claude desktop app

Where you build prototypes. Download it and sign in with your ThoughtSpot account. You'll work in its Code tab, which runs git and npm for you. Mac and Windows.

claude.ai/download
Step 1

Fork the repo

A fork is your personal copy. Changes you make only affect your version — never the original.

1

Go to Radiant Play on Galaxy

Open galaxy.corp.thoughtspot.com/mohammed-faris/radiantplay

2

Click "Fork" in the top right

Galaxy creates your personal copy under your account — takes ~10 seconds

3

Copy your fork's clone URL

On your fork page, click the green Code button → copy the HTTPS URL. It looks like:
https://galaxy.corp.thoughtspot.com/your-name/radiantplay.git

Step 2

Get it running on your machine

Steps 1 to 3 are one-time only. After that, just "Start it up" each time you come back.

Open the Code tab
Open the Claude app and click Code at the top. Start a new session and choose a folder to work in. Documents is fine; this is where your copy of the project will go.
# Pick a parent folder, for example: ~/Documents
Clone your fork one-time only
Paste your fork URL into the chat and ask Claude to clone it. Claude downloads the project into a radiantplay folder.
⚠ If Galaxy asks you to sign in: run the clone in the app's terminal panel instead, so you can type your login.
# Type this in the chat: Clone https://galaxy.corp.thoughtspot.com/your-name/radiantplay.git here # Replace "your-name" with your Galaxy username
Open the project one-time only
Start a new session and choose the radiantplay folder this time. From now on, always open this folder. Claude reads the project's rules from it, so it already knows the Radiant components, tokens and conventions.
# Your session folder: ~/Documents/radiantplay
Start it up every session
Ask Claude to start the dev server. The first time, it installs the project's packages too (about a minute). The app opens a preview pane that updates as Claude makes changes.
⚠ If Node.js is missing: Claude will tell you. You need Node 22 or newer: install the LTS from nodejs.org, then ask again.
# Type this in the chat: Start the dev server # Two URLs to know: localhost:5173 ← Radiant DS browser (components, tokens) localhost:5173/playground ← YOUR prototypes live here ✓

Slash commands

Type /rp- to see them all

Type them in the Code tab chat. Each one walks you through a task step by step.

Build
/rp-new-prototype Name
  • Scaffold a prototype folder and add it to the gallery
/rp-radiant-check Name
  • Health check: components, tokens, content and layout
/rp-explore scope
  • Step outside Radiant to try a freeform direction
/rp-migrate-prototype
  • Move your prototypes onto the Geist font and dark mode
Stay current and share
/rp-sync-upstream
  • Preview the latest library changes, then pull them into your fork
  • Asks before it merges anything
/rp-coolify-deploy
  • Give your fork a live URL that redeploys on every push
/rp-project-canvas
  • A local overview of your prototypes, branches and sites
💬
No command for it? Just ask. "Capture a thumbnail for my prototype" or "Switch my prototype's AI to Sonnet" work too.
