Data Studio — POC scope

2026-08-06 · for product, engineering, and the data-modeling team · includes review feedback

POC is the cut we build and spec against. Vision is long-term — prep transforms, code blocks, the fuller agentic surface. Demo is finished and is not under review.

The cut rule. A feature makes POC if it serves one of the three problems in §1. Everything else waits. And every control that ships is wired or removed — a cosmetic control gets spec'd as real.

The seam — the one thing the agent has to be able to do

Three calls in ModelCanvas.tsx. This is the entire API between a conversation and the canvas.

CallDoes
agentAddTablesPlaces table cards. Returns a promise
agentAddJoinsDraws joins, runs auto-layout
agentAddPythonSourceAdds a Python source card — out of POC scope

If the SpotterModel agent can call these, it can drive POC's canvas. Caching is not on this list — agent-driven caching is a new call, not a wiring job.

4.  What's there, what's missing

Built and working

  • Canvas — cards, chip pipeline, orthogonal joins, auto-layout, Tidy up
  • Data browser tree with column selection
  • Join, filter, formula via UI + properties panel
  • Spreadsheet grid, column menu
  • Caching — configure, enable, progress
  • Publish — modal, draft→published
  • Node-level and model-level preview

Gaps to fill

  • Formula and filter are per-table. Confirmed in review — they need to span the model
  • The entry CTA doesn't exist. Today the only route to the canvas is the conversation
  • Three datasets are live at once. The journey builds a marketing model; the browser lists customer-support tables; readiness describes a third set
  • Caching has no schedule and no in-progress contract. Nothing says what's usable while it runs
  • Published model view is undefined for MVP
  • Undo is partial. Canvas undo works; spreadsheet undo/redo are dead buttons; Tidy up has no undo
  • Parameters, Settings. Never built here
  • Cosmetic controls to remove: spreadsheet formatting toolbar (10 of 15 dead), "Fix all with agent" chip, WorkflowDirectory

Two review items where the prototype already holds evidence

QuestionWhat the prototype shows
Spreadsheet vs data preview Preview (bottom pane): output of the pipeline at a chosen node or the whole model, Data and Semantic tabs, read-only, row count. It answers "what did this step do?"
Spreadsheet (top tab): full-pane grid, column menu, formula columns with an fx badge, opening it clears canvas selection. It answers "let me work in the data."
The overlap is real — both render the same rows.
Agent-led creation — chat or canvas? Built as canvas: the chat panel sits on the canvas, and accepting the agent's first table proposal creates the model. Full-screen chat was considered and rejected — it's a different visual treatment, so the conversation has to be handed across a seam mid-flow. One flex row, nothing mounts or unmounts. Currently Demo-only (chatFirstStart).

5.  Validated vs to be validated

  • Feasibility — what the backend already supports vs what gets built. Not yet asked
  • The old-canvas gaps — whether losing Parameters and Settings is acceptable
  • That prep being out is survivable — it's one of the five documented user problems, deferred to Vision
  • The user, at all — knowledge/users.md carries four open questions about the primary user, all unanswered

6.  Decisions blocking the build

  1. Where the CTA lives. Entry point is settled — a CTA, no Data Studio home in MVP. Only the location is open. Product
  2. Formula and filter at model level. Confirmed rework. Same decision as node-vs-model level — settle once. Product + Design
  3. Spreadsheet and preview — both, or one? Evidence in §4. Product + Design
  4. Is the clarify→plan→build conversation ours or a placeholder for the SpotterModel agent? Decides whether we invest in the conversation or only in the seam. Product + SpotterModel
  5. Caching contract. Scheduling, duration, and what a user can do mid-cache. Plus whether the agent drives it — that's a new seam call. Product + Data-modeling
  6. One dataset. Which of the three the whole POC runs on. Product
  7. Publish and Draft — build or not? Both exist in the prototype. Product + Engineering
  8. What can the modeling team plug vs what gets built? Parameters, Settings, cross-table filters, agent-driven caching. Data-modeling team
  9. Readiness label — "Spotter readiness" or "AI readiness". One ships. Product + Komal
