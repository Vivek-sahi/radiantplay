Spreadsheet <> Canvas interaction and Spreadsheet actions update

Spreadsheet <> canvas interaction model

Proposed model

  • Don't default to model.
  • Clicking on card to trigger preview.
  • Have an explicit model preview button.
  • Clicking on the canvas doesn't change the preview.
  • How to refresh data needs to be discussed with engg once.

Why not the eye icon

  • In majority cases, users will want to see the data in the object, so we should make that path easier.
  • Other tasks like join, remove won't happen often, so we should keep them in a triple dot menu.
  • For drag, there is an established behaviour: you click on an object and hold to drag. Hence we should not worry about drag.

Spreadsheet actions

On what level can the user take actions?
Current canvas allows only model level. But we should not impose this behaviour on spreadsheet. In spreadsheet, users will apply filter and formula or any other action on the columns they're seeing. They should be allowed to act on the data that is in front of them without requiring to switch to a model view.
Does a spreadsheet performed action get added to the model or is it treated as only exploratory?
Is the user doing disposable calculation/explorations or are they modeling?
Option 1Every user action is promoted to the model level.
  • Hunch is with data preview available, more and more user action will get initiated from the data preview. Requiring an extra step to promote adds extra friction in that path.
  • Values show up in left panel model inventory serving as instant feedback for user.
  • The behavior is same from everywhere. Whatever you're doing, you're modeling. If you don't want, you can remove. It is not being auto-published, there is a save button so there is no risk of it causing pollution.
Option 2Action from spreadsheet are treated as disposable action that require a promote step.
  • If most user actions are just ad-hoc explorations and not for the final model then option 2 is better.
  • But this also introduces a separate state where an action is performed and not promoted and then we'll need to design a path for promotion to model. Either with the save modal or inline with the actions.
