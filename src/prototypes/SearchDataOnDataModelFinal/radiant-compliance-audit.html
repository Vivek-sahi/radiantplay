Icons

QueryAsIs.tsx carries 74 inline SVGs. Standing rule: icons come from the Radiant Icon registry. Split them three ways:

  • Swap — registry equivalents exist: funnel → filter, magnifier → search, download/upload, chevron-up/down, more, plus, table, expand/fullscreen, formula (the toolbar already uses Icon name="formula"; the col-menu FxIcon duplicates it inline).
  • No registry equivalent yet: sort-asc / sort-desc / advanced-sort / clear-sort (registry has only sort), filter-remove ✕, duplicate, rename. Either add to the DS or hand the SVGs over as specced assets.
  • Deliberately custom (keep): crow's-foot join ends, join capsule badge, the promote/demote arrows in the filter menu, grid dot pattern.

Layer 4 · Screens vs DS practice

Copy & casing

  • DS rule is sentence case everywhere. Current labels with capital M: "Save Model", "Promote filter to Model", "Remove filter from Model". These are your rulings from today — flagging only so the handoff records them as intentional (or normalises to "Save model" etc. — your call, one word).
  • Buttons elsewhere are imperative and sentence case ✓ ("Preview model data", "Add filter", "Dismiss").

Filter behaviour (state machine, as ruled today)

  • Grey funnel = applied to preview only · blue = in the model. Menu: Edit filter · Promote filter to Model ⇄ Remove filter from Model · Delete filter (always last; on a model filter it removes from both).
  • The modal's "Add this filter to this model" checkbox now appears in both creation options — seeded checked in direct mode, to current membership when editing. Unchecking on edit = remove from model, filter stays grey.
  • Edge handled: out-of-scope filter configs go inert (never zero-out); deleting a filter's column scope survives re-entry via per-scope signatures.
  • Dev note: promoted state derives from the model's filter list (single source of truth) — keep that derivation in the product build rather than duplicating a flag.

Formula behaviour

  • Open ruling — handoff blocker: the fx bar speaks Excel-style (from the Spreadsheet Figma); the filter modal and the product's "Spreadsheet on live data" EA are TS-formula-language-native (docs 26.9.0.cl explicitly reject Excel syntax). Recommendation on file (grid-as-workbench.html): one language, two ergonomics. Needs your decision before dev picks this up.
  • The fx-bar "Add to model" checkbox is now removed (user confusion); promotion paths are the column ▾ menu and the Save Model review sweep — both survive handoff cleanly.
  • Validation exists (trailing-operator, empty states) but error presentation is a red outline only — DS error practice wants a message; spec it for dev.

Layering & overlays (fixed today, but document for dev)

  • The preview panel is a stacking context at z-index 30 so its modal overlays and menus beat the canvas pills (z 20). This works but is order-sensitive — the real fix for the product build is portal modals (and menus) to body; RdModal currently renders in place with a z-1000 overlay.
  • Shared Tooltip shows on focus as well as hover; click-focus pinned tooltips until blur. Fixed locally by preventing click-focus on the sheet toolbar. The DS-level fix (show only on :focus-visible) would solve it for every consumer.

Accessibility quick pass

  • Good: aria-labels on funnel/chevron/toolbar buttons, role="tooltip", aria-disabled pattern.
  • Gaps for the product build: hand-rolled menus have no keyboard navigation or focus trap; the sheet grid has no roving tab-index; colour is the only promoted/preview signal on the funnel (blue vs grey) — pair with the menu labels it already has, fine, but note for a11y review.
